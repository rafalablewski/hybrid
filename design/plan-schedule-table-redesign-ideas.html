HYBRID — schedule table redesign

Take away everything
until only the training remains.

The programme day card is structurally right — exercises down, loads across, reps where they meet. But on screen it still speaks like a spreadsheet: three stacked header strips before the first rep, a different colour for every column, phantom columns of empty space, and glyph-heavy cells (×4+1×4) that make a simple prescription look like an equation. The data is good. The table is loud.

These ten ideas apply one discipline — the one Jony Ive practised at every scale: simplicity is not the absence of things, it's the absence of everything that isn't the point. Order over chaos, achieved by subtraction; hierarchy carried by light and type instead of boxes and stripes; colour spent only where it is information; and the deepest care put into the details nobody will consciously notice. Nothing in the prescription is removed anywhere below — some of it just stops shouting, and some of it moves one honest tap away.

What the current table gets wrong

Four faults — all of them additive, none of them data
01Header stack

A PM session opens with PM — 89 LIFTS, then MAIN (3 EXERCISES), then EXERCISE / 60% / 70% / 80% / BW — three full-width strips, two of them tinted, before a single rep appears. The chrome outweighs the content.

02Rainbow columns

Blue, lime, sand and ash all fire at once on every table. When every column carries a colour, colour stops meaning anything — the eye has nowhere to go first.

03Phantom width

Load columns are derived per group, so a BW column used by one Good Morning stretches empty across every other row, and names truncate to make room for voids.

04Glyph noise

×4+1×4 is four symbols and three numbers for "four sets of 4+1". The leading × is pure notation debt — it exists for the parser, not the athlete.

Idea 01 Reduction
Collapse the header stack — one rule line, not three strips

The session marker, the group label and the column header are all metadata about the same rows — so they share one header line. The session's time-of-day sits where "EXERCISE" sat (it was labelling the obvious), the group label rides beside it in quiet ash, and the lift count takes the right edge where counts live everywhere else in the app.

  • Nothing is lost: AM/PM, group name, exercise count, lift volume and every % column are all still stated — once each.
  • The tinted band backgrounds retire; the session colour survives on the session word itself. A second group in the same session ("Accessories — 5") gets its own single line.
  • Two strips and two tint washes fewer per session ≈ 30% of the card's vertical chrome gone before any row changes.

Idea 02 Restraint
Retire the rainbow — let ink weight carry intensity

Load already climbs left to right; the colour ramp restates what position says. Instead, intensity becomes ink: cells gain opacity and weight as the percentage climbs — 60% whispers, 75% is bold — and the single accent (chartreuse) marks only the heaviest work of the day. The eye lands on the one cell that defines the session, which is exactly the question an athlete asks a table.

  • One accent per cluster — the standing house rule the current rainbow breaks.
  • The freed colours go back to being semantic: RPE heat, session identity, risk. Colour returns to meaning something.
  • Cheapest idea on this page: a style-map change in both matrix renderers, zero structure touched.

Idea 03 Honesty
Say kilograms when you know them — the % becomes the footnote

A percentage is an instruction for a calculator; a kilogram is the thing you put on the bar. Once the ledger above the table holds a max, the column headers morph in place: the kilogram figure becomes the headline, the percentage drops to small print beneath it. Empty ledger, and the table honestly shows percentages — it never pretends to know a number it doesn't.

  • Both truths stay visible — 59 kg over 60% — so the programme's logic is never hidden behind the arithmetic.
  • The morph is the reward for typing a max: the ledger's live echo (→ 59 kg @ 60%) already promises this; the table should keep that promise.
  • The maths already exists in planProgramView — today it's computed and then largely unspent.

Idea 04 Silence
Kill the phantom columns — outliers become lines, not lanes

Empty cells are honest silence, but an empty column is dead architecture: a lane the whole table pays for so one exercise can use it. Columns should be derived per contiguous run of lifts that share loads — and an exercise whose loads match nobody (the lone bodyweight Good Morning, a single 90% single) drops out of the grid into a full-width row carrying its complete prescription in words.

  • Names stop truncating — Power Clean & Jerk gets its letters back from the empty BW lane.
  • The grid earns its geometry: every lane that exists is used by most rows that cross it.
  • Derivation lives in packages/core next to planProgramView, so web and mobile can never disagree about which columns exist.

Idea 05 Care
Pin the exercise column; fade the edge instead of cutting it

A long Soviet ramp can hold six loads, and today the whole table — names included — scrolls sideways, so by 80% you no longer know whose reps you're reading. The fix is the one every good instrument makes invisibly: the name column pins while the ramp slides beneath it, and the clipped edge is a soft gradient fade, not a hard cut — the material itself says "there is more", no chevron needed.

  • A faint cast shadow under the pinned column gives the slide depth — light doing the work of a border.
  • Web: position: sticky on the first cell. Mobile: the name column renders outside the ScrollView — both are small, shipped patterns elsewhere in the app.
  • Pairs with Idea 04: fewer phantom lanes means most days never need to scroll at all.

Idea 06 Typography
Quiet the notation — reps speak, the × steps back

Ive's teams sweated the parts nobody consciously sees; in a training table that part is the multiplication sign. The leading × on every cell is parser residue — drop it. The remaining × renders a shade of ash lighter than the digits, with a thin space either side, so 4 ×3 reads as a rhythm, not a formula. Cells align on the × via tabular figures, so a column of prescriptions becomes a column of matched shapes.

  • The grammar — reps × sets at the header's load — is stated once, in the card's mono foot, instead of being re-implied by every cell.
  • Complex sets keep their full truth: 4+1 ×4 still says four quads-plus-one-jerk, only calmer.
  • One formatting function in core, shared by both clients and by Today's session runner — the notation becomes a product-wide voice.

Idea 07 Form reveals work
Give the day a pulse — its load shape, drawn in the header

The week rail already renders the plan's volume as a waveform, so the shape language exists. Bring it down one level: beside the day's lift count, a load spark — one hairline bar per prescription, height from load × reps, the top-intensity touches in chartreuse. Before reading a single number you know whether Day 1 is a grind, a spike day, or a taper.

  • This is the same "shape before numbers" argument that earned the waveform rail — applied to the day, keeping parent and child speaking one language.
  • Strictly semantic, so it passes the no-decoration rule: every bar is a real prescription; delete a set and the pulse changes.
  • Computed in core from data the view model already has. Nothing new is asked of the plan authors.

Idea 08 Focus
One day open at a time — the week becomes an accordion

Six days × three tables is a wall; nobody trains Wednesday while reading Saturday. Each day collapses to a single honest line — title, a plain-words summary of what the day is, its lift count — and exactly one day is open at a time. Enrolled, today's day arrives open; browsing, Day 1 does. The wall becomes a week you can hold in one glance, with the detail one intentional tap away.

  • No data is deleted — every table still exists at full fidelity inside its day; only simultaneity is removed.
  • The closed-row summary is new information the wall never offered: what each day is, before what it contains.
  • The expand ride shares the accordion mechanics already prototyped in reference/glass-card-accordion.html; Reduce Motion gets an instant swap.

Idea 09 Depth, not density
The exercise sheet — every row can be pressed for its full story

A table cell can hold "3 ×2"; it cannot hold why. Any exercise row presses into a Liquid Glass bottom sheet that unpacks the whole prescription at reading size: each load as % and kilograms, reps and sets in words, the author's note given room instead of a squeezed second line, the max it's computed from, and the door to that lift's history. The table stays terse because depth is one tap away — density moves off the surface, not out of the product.

  • This is the "sheet" answer to the brief: the table doesn't have to carry everything if the sheet carries the rest.
  • Long notes (@ 90–110% of clean) stop truncating forever — the sheet is where they were always meant to breathe.
  • Same sheet component both clients already use for session detail; the row press is the only new wiring.

Idea 10 Material
Dissolve the card — the schedule becomes a full-bleed ledger

The maxes above the schedule already live as hairline rows directly on the ink; then the schedule suddenly re-boxes itself into bordered cards. Drop the box: each day becomes a ledger section whose hairlines run edge to edge under the physical screen (the standing full-bleed idiom), separated by space and a sticky day header that picks up glass blur as rows slide beneath it. Depth comes from light and layering — never from a border.

  • One material from cover to last row: the whole plan page becomes a single continuous document instead of a stack of containers.
  • Roughly 32 dp of width returns to the columns — on this table, that's a whole extra load lane before scrolling.
  • The sticky blurred day header is the same recipe as the collapsed cover bar — the screen keeps one depth story.

How they compose

Three coherent directions — not ten separate bets

QUIETThe quiet matrix — 01 + 02 + 04 + 06

The pure-subtraction release: merge the header stack, retire the rainbow, drop phantom columns, calm the notation. No structural or behavioural change — the same table, with everything that wasn't the point removed. Ship this first; every later direction builds on it.

ALIVEThe honest table — 03 + 05 + 07

The table starts answering back: kilograms when a max exists, names that never abandon their reps, a pulse per day. Adds the small pieces of engineering (sticky column, header morph) that make the surface feel considered rather than styled.

CALMThe focused schedule — 08 + 09 + 10

The largest move: the wall becomes an accordion of days on a full-bleed ledger, with an exercise sheet carrying the depth. The screen shows one day's work, beautifully — everything else is a glance and a tap away. Prototype behind the enrolled state first.

BUILDParity in one change

  • packages/core — column derivation (04), notation formatter (06), kg morph (03) and the day pulse (07) all live beside planProgramView, so both clients read one truth.
  • Mobile percent-program.tsx + web program-days.tsx change in the same commit — the parity rule, kept by construction.
  • House rules hold throughout: single accent per cluster, no middots (en dashes in header lines), no decorative markers — the pulse and heat are semantic, every bar a real set.
  • Web keeps a real <table> with column scope; the sheet and accordion are focus-trapped and Reduce-Motion-safe.
