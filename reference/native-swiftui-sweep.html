Which is the sharper brief anyway. A material is a look. A button knows how big a thumb is, what a long press means, how to be read aloud, how to look disabled and how to bounce when it lands — and an animation that runs inside a SwiftUI transaction never negotiates with JavaScript to draw a frame.

Buttons and pills

six swaps
01

Forty-nine hand-rolled pills converge on APill

APill — the app's own drawing, deliberately. Not a native Button.

This is the swap I got wrong first time. I proposed replacing the brand pill with a native Button — which this codebase already tried: a GlassPillButton wore Log set, Finish and the primary APill, and was reverted on the grounds that a full-width chartreuse CTA has no system counterpart. The decision is written into swiftui.tsx and repeated in capabilities.ts. It stands.

The real fault is adoption. APill is used at 61 sites and already owns the hard parts — four variants, the neutral soft one on real Liquid Glass, and a commit state that holds its width so the button cannot resize mid-save. Another 49 pills never went through it, each picking its own padding, radius and face. That is design-system drift, and the cure is migration, not a native control.

02

Size becomes a word, not a padding pair

controlSize('mini' | 'small' | 'regular' | 'large' | 'extraLarge')

Every button in the app declares its size as two numbers and a font size, chosen by eye at the call site. controlSize names it instead — and the named sizes stay in proportion to each other, and to the user's Dynamic Type setting, which hand-set padding cannot do.

03

Filter chips become Toggles that look like pills

Toggle + toggleStyle('button')

Every chip row in the app — muscle filters, sport categories, date ranges — is a Pressable holding its own boolean and swapping two hand-written styles. A Toggle with the button style is exactly that control, and it announces itself as a toggle: VoiceOver says "selected", the state survives Dynamic Type, and the on state is drawn by the system rather than by a ternary at the call site.

05

An icon-and-word button stops being two components

Label + labelStyle('automatic' | 'iconOnly' | 'titleAndIcon')

Today a glyph beside a word is a View with a Text and an Image, aligned by hand, and a narrow screen either wraps it or clips it. A Label is one unit: the system aligns the glyph to the text's baseline, keeps the optical spacing at every size, and labelStyle lets one component drop to icon only where space is tight instead of a second component existing for that case.

A row of sibling actions becomes a ControlGroup

A Picker is for choosing one of several. A ControlGroup is for actions that simply belong together — Skip, Move, Start on a plan day; Edit, Duplicate, Delete on a routine. The app draws those as loose buttons with a gap, so nothing says they are one cluster, and each carries its own border.

Transitions

four swaps — where the frames are drawn

Every animation in the app is JavaScript telling the native side where things are, sixty times a second, over a bridge that is also carrying everything else. SwiftUI's model is the opposite: you hand it a target value inside a transaction, and it animates itself there on the UI thread. Nothing crosses per frame, so nothing can stutter because a fetch resolved mid-gesture.

07

Animation moves onto the UI thread

withAnimation(Animation.spring) + useNativeState — worklets, no per-frame bridge traffic

withAnimation takes a worklet that mutates useNativeState values, and runs it inside a real SwiftUI animation transaction. The JavaScript side names the destination once; the system draws every frame between here and there. It is the same physics the app already encodes in its springs tokens — response and damping fraction — so the motion language does not change, only who is drawing it.

Before — JS drives every frame
bridge — competing with a fetch
a dropped frame is a visible stutter
Fine at rest. Not fine while the screen is also loading.
After — the system draws it
UI thread — one value, one transaction
smooth under load, because load is elsewhere
Interruptible mid-flight and still resolves correctly.
08

Numbers roll instead of cutting

contentTransition('numericText') + monospacedDigit

Every figure in the app hard-cuts when it changes — the day's distance, the set count, the tonnage, the macros. numericText rolls the digits that actually changed, in the direction of travel, and monospacedDigit holds the column still while it happens so nothing beside it shifts.

After — digit by digit

Collapses to instant under Reduce Motion, automatically.
09

Glyphs react — the state change happens on the mark itself

symbolEffect — bounce, pulse, breathe, wiggle, rotate, variableColor, drawOn

Eleven effects ship with the modifier, and they are the cheapest feedback in the system: a session lands and the mark bounces; a set is syncing and it pulses; a rest timer is armed and it breathes; a wrong entry wiggles. Today these moments are silent, or they are a toast that covers content to say something the glyph could have said in place.

After — the mark answers

10

Expanding a section stops being a measured height

DisclosureGroup — replaces the hand-animated Collapse in percent-program

Expanding anything in the app means measuring the content, animating a height to that number, and clipping. It janks on first open because the measurement lands a frame late, and it fights Dynamic Type because the measured number is now wrong. A DisclosureGroup owns its own disclosure state, its chevron rotation and its expansion — and it never needs to know the height, because the system laid the content out.
