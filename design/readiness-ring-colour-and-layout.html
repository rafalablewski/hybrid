HYBRID — design study — Performance → Your state

The ring says a −3 is half your day.

The readiness ledger is arithmetically sound: 100 − 30 − 14 − 3 = 53, and the engine guarantees it. What is wrong is the paint. The kept arc takes the readiness band's colour, the wearable cost takes caution's colour, and at a score of 53 those are the same sand. So the legend's little yellow square — worth one tick — points at seventeen of them. This page proposes four ways to fix the colour, and one new layout for the block.

01

The collision is structural, not a one-off

The kept arc is coloured by readinessRole(score) — chartreuse at 80+, teal 60–79, sand 40–59, terracotta below. The three causes are fixed at terracotta, teal and sand so a cause means the same thing on every surface. Those two sets overlap in every band: there is no score at which the ring is honest by luck.

ScoreKept arcCollides withWhat the athlete reads
80–100 chartreuse — nothing honest, by accident: no cause is chartreuse
60–79 teal Conditioning load conditioning looks like most of the ring
40–59 sand Wearable readings today: a −3 owning 17 ticks
0–39 terracotta Tissue load the whole ring reads as one injury warning

The spec anticipated this — “on a bad day both are red; weight, not hue, is what says which part of the ring is still yours” — and that reasoning holds for a shape you stare at. It does not hold for a legend, where a 8×8px swatch is the only bridge between a row and an arc. The moment the ledger opened, hue stopped being decoration and became a lookup key.

Worth noting for Kyoto Hour: in the light theme sand darkens to #875427 and terracotta to #a3442f — a brown and a vermilion, closer to each other than their dark-theme twins. Whatever we pick has to survive both grounds; every ring below is rendered in the live theme, so flip your OS setting to audit it.

02

Four ways to make the ring tell the truth

Same engine, same geometry: each ring below runs the real apportion() and the real minimum-arc rule over 32 ticks. Only the paint differs. Each option is shown across three days — a 78 (teal band), the 53 from your screenshot, and a 31 (terracotta band) — because an option that only works on a good day is not an option.

04

What it takes to build

  • The colour rule moves into core. The clients currently decide the kept arc's paint inline, in two places, and both got it wrong the same way. A single readinessRingTicks() that already knows the kept run should hand out the roles, so a client cannot re-introduce the collision.
  • Cutting the prose changes what the door counts. Today the count is readinessReasons().length — the sentences. With the sentences gone it has to become the number of ledger rows, or the door promises three of something that no longer exists. Both happen to be 3 today, which is exactly how that bug would ship unnoticed.
  • The bar is the ring's data, not new data. It reads the same segments, so it cannot disagree with the arcs above it — and it inherits the minimum-arc rule, which is what keeps the −3 visible.
  • Both clients, one change (web aurora/performance.tsx, mobile aurora/performance.tsx), plus a test that fails if the kept colour ever equals a cost colour in any band, on either theme.
