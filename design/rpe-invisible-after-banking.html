Live logger – defect, four treatments, shipped

The invisible RPE — the number you tapped, banked and never saw again

You set RPE on a set, log it, move to the next one — and the effort you rated is gone from the screen. It is stored, it saves, and the session breakdown prints it back to you at home. It just isn't drawn on the live logger's banked row, because that row is built from exactly two facts and RPE is not one of them.

What happens, in two frames

apps/mobile/app/workout.tsx

The active set carries RPE on an amber chip in its label row. The moment the set banks, the whole block collapses to a one-line ledger row — and that row renders a badge, a load × reps summary and a check. The chip's value has nowhere to land, so it simply stops being drawn.

So this is not a state bug, and that is worth saying plainly because it changes the fix. s.rpe holds the value; the save at workout.tsx:1022 writes it onto the block; and app/session/[id].tsx:223 prints RPE 8 beside every set in the breakdown. Exactly one surface in the chain doesn't render it, and it happens to be the surface you are looking at while you train.

The token

A dedicated column
Shipped
  • +The value stays the colour it was when you tapped it — amber, labelled, same words as the chip it collapsed from. Nothing to relearn.
  • +It renders nothing when RPE is unset, so the row only grows a fourth column when there is actually something to say. Simple mode and unrated sets are untouched.
  • +Keeps the concern channel usable: riding inside the summary string would fuse effort with the amber/terracotta a plausibility warning uses, so the row could no longer say which fact it was reporting. A separate column can at least yield.
  • −It does not escape that collision, it only survives it — and the first version of this page claimed otherwise. It said the token was drawn in sand and the summary in amber, as if those were two channels. They are one constant: C.amber is sand. On a caution set both columns went the same colour. Shipped fix: the token carries the chip's amber normally and drops to ash on a flagged set, where the amber belongs to the figures.
  • +Matches the session breakdown's own RPE 8 token, so the live row and the at-home row finally read alike.
  • −A fourth column. The row's own comment warns it is already three wide on a small phone; at fs.nano with the label it costs about 44dp, and a 5-char load plus a long unit is the tight case.
  • −Under the RIR swap the label has to swap too (RIR 2) — one more thing that must read from rpeRirSwap rather than the raw field.

The notation

Fold it into the summary string
Cheapest — one line changed
  • +Zero layout risk. One expression in one file; no new column, no new measurement, nothing to reflow on a small phone.
  • +100 × 5 @ 8 is the sport's own notation — the way an RTS-lineage lifter writes a set down. No label needed because the @ is the label.
  • +Naturally extends the "Last time" line and strengthSetsSummary, so the reference above the sets could carry effort with the same helper.

The series

One effort line per exercise, not per row
Strong as a companion, weak alone
  • +It answers the question you actually ask mid-workout: is effort climbing? A per-row number makes you read three rows and hold them in your head; the series is the shape.
  • +Costs the rows no width at all — the row keeps its three columns and the small-phone worry disappears.
  • +Sits naturally where the exercise's own summary belongs, under the sets and above Add set.
  • −It breaks the tap-to-fix loop: the series says a 9 happened but not on which row, so correcting a mistyped effort means guessing which set to re-open.
  • −A new full-width element in a card that just spent a redesign removing a meta row. It has to justify itself against that, and "restores a lost value" is a weaker case than "adds a reading you couldn't get".

The tint

Effort as colour, no number
Rejected — and worth writing down why
  • −That colour is already spoken for. The summary goes amber for a questionable set and terracotta for a refused one. Paint effort in the same hues on the same text and the row can no longer tell you which fact it is reporting — the frame above is the ambiguity, not a mockup of it.
  • −It doesn't return the value. You rated an 8; a warm row is not an 8. The complaint is that a number went missing, and a tint answers a different complaint.
  • −Colour-only encoding fails the accessibility floor the rest of the logger holds — nothing for VoiceOver to read, nothing at all for a red-green deficit.
  • +Its one virtue, kept for whichever option ships: the amber belongs on the value, not on a badge — the row shouldn't grow chrome for this.

What shipped

The token, and all three findings below it

The token, plus one formatter for one set — and the effort no longer carries forward.

The token was the honest fix: it returns the exact value, in the exact colour and wording it had on the chip, on the row that owns it. It rides inside the row's re-open target rather than beside it — the number you want to correct is the likeliest reason to tap the row, so it had better be part of the button — and it renders nothing when RPE is unset, so the tight small-phone case pays nothing in the common case. The summary's amber stays free to keep meaning "check this number".

The row now also reads its load × reps line through a new shared strengthSetSummary(name, set, { style, units }) — the per-set half of strengthSetsSummary, with a "compact" style for the comma list and a "row" style for the ledger, so the two readers keep their different dash conventions without keeping two implementations. All three findings below shipped in the same change: carry-over no longer copies the effort, and the RPE disclosure is keyed per set.

The series is the better idea about training and the worse idea about this bug — it belongs in a later change, on its own argument, with the per-row token underneath it. It is not a substitute for the value that went missing.

Three more things in the same code

Found while tracing the field — all three fixed alongside it

workout.tsx:850 – emptySet(prefs.carryOver ? … )

Carry-over copies the effort forward

carryOver is on by default and emptySet copies rpe along with load and reps — so a fresh set arrives already rated at the last set's effort, before you have done it. Load and reps are a plan worth carrying; an effort rating is an observation, and it should almost certainly start blank.

workout.tsx:356 – rpeOpenUid

The disclosure is keyed per exercise, not per set

Only the active set draws the pill row, so it works today — but banking a set never clears the state. Open the RPE row, don't pick anything, log the set, and the row is now sitting open on the next set. Keying it to the set's uid (or clearing it on bank) makes the state mean what its name says.

workout.tsx:1674 vs core strengthSetsSummary

Two formatters for one set

The row's inline summary only special-cases pure bodyweight, so a bodyweight-plus or assisted lift prints as plain load × reps here while the shared strengthSetsSummary above it writes +20×5 / −20×5. Whichever option ships, the row should read through the shared formatter — that is also where @ 8 would live if you preferred the notation.

Cards are rendered from the product's own tokens (packages/core/src/theme/tokens.ts) at real sizes — fs.nano 10, fs.caption 12, fs.body 13, fs.stat 46, RADIUS.card 28, RADIUS.mark 3 — so what you see above is what the change looks like on device.
