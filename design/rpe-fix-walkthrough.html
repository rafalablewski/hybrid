apps/mobile/app/workout.tsx — emptySet

Carry-over stopped copying the effort

A new set arrived pre-rated at the last set's RPE, on an amber chip indistinguishable from one the athlete had actually judged — and if they never touched it, that guess was what saved. Load and reps are a plan worth carrying; an RPE is an observation of a set that has happened. The Builder's carry-over still copies it, and should: there an RPE is a prescription, authored in advance.

The motion that was never there

Flip Motion off above to feel what shipped

Reported separately, and the larger finding: "I think I never saw them in my app." Correct. Four things were checked before anything was changed, because a no-op in motion code is invisible and guessing at it wastes a device build. The plumbing turned out to be sound — against the installed RN 0.85.3 the JS gate isLayoutAnimationEnabled and the C++ enableLayoutAnimationsOnIOS both default true, so the first suspicion (that newArchEnabled makes LayoutAnimation a no-op under Fabric) was wrong for this version. useReducedMotion defaults false. The tokens are real. The defect was simply that animateListChange was never called for eleven of the layout changes the logger makes.

It sat under a comment reading "EVERY MUTATION OF THE LIST TRAVELS", which is how it survived: the sentence meant the exercise list, said "the list", and read like a guarantee. The fix is a door — commitSets arms the animation, then commits — so the seven set mutations cannot forget. The four block changes are not set mutations, so they arm it themselves, and the three ways to dismiss the rest banner were collapsed into one stopRest so they cannot disagree.

Four things still do not animate, deliberately. Renaming a lift writes per keystroke. setSetField and the load stepper change a value inside a row that stays put — animating those would spring the card on every digit. The drag commit stays still because the displaced rows are already standing in their new slots, and a layout animation would drag them back across a distance they had just crossed. And the hydration paths replace the whole board on load, where there is no prior position to travel from. Each is named in apps/mobile/lib/list-motion.test.ts with its reason — an allowlist rather than a count, because the exemptions are judgements, and naming them forces whoever adds the next one to decide which kind theirs is. That is the decision that got skipped eleven times.

The 21 that were not there. For most of this session @hybrid/web typecheck failed with 21 errors saying SessionSet, SessionStream and SessionLap do not exist on PrismaClient. They were reported here as pre-existing and out of scope — twice — which was the wrong call. The models do exist (prisma/schema.prisma lines 983, 1073, 1133); the generated types did not, because nothing in a fresh container runs prisma generate — there is no postinstall hook, and only build does it. One command cleared all 21. Vercel was never affected (build generates first) and neither was CI (which generates immediately before its typecheck step, for exactly this reason). Only the sandbox was stale — and it would have been stale for every future session, producing 21 errors indistinguishable from real ones, naming real files and real models, whose obvious "fix" is to edit working code. The SessionStart hook now generates the client, mirroring CI. pnpm typecheck passes across all three packages.

This page is checked, not just written. The simulation above needs plain-JS copies of four functions to run standalone, and a demo that quietly disagrees with the code is worse than no demo, because it is convincing. apps/web/__tests__/demo-port-fidelity.test.ts therefore reads this file's own script — everything between its PORT:START and PORT:END markers — evaluates it, and sweeps it against @hybrid/core across all 882 combinations of lift, load, rep count, unit and style. Nothing is duplicated in the test; change strengthSetSummary and this page fails the build until it is updated too. It was confirmed to fail: breaking the port's sign logic turns 6 passes into 2 failures naming the exact case.

Both formatters, displayLoad, rpeRirSwap and RPE_SCALE in this page are ports of the real source, and the phone is drawn from the product's own tokens at real sizes — fs.nano 10, fs.caption 12, fs.body 13, fs.stat 46, RADIUS.card 28, RADIUS.mark 3.
