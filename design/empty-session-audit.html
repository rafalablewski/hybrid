3 – The redesign

Nothing here is a new feature. Every capability on the screen today survives; almost all of them stop being a permanent object and become something you reach for.

Simplicity is not the absence of clutter. That's a consequence of simplicity. Simplicity is somehow essentially describing the purpose and place of an object and product. Jony Ive

The set is the screen

One exercise, one surface, one set in focus. No panel inside the card, no summary of the row you can already see. The card is the exercise; the number is the set.

The default is the answer

You did 5, 5, 5, 5, 5 last time. So the queue is five sets of five, pre-filled, in chalk not grey. Logging set one is one tap. A placeholder zero asks a question the app already knows the answer to.

One accent, one go

Chartreuse appears exactly once, on Log set. The exercise mark, the add glyph, the exits and Finish all go to chalk and ash. Amber survives only as paused; blue only where a rest is armed or running. Those two are state, not decoration — they earn their colour by changing.

The thumb owns the primary

Log set docks above the home indicator and stays there whatever the session length, with Pause and Finish flanking it as glass satellites. Between sets the same dock becomes the rest countdown — the dead third of the screen becomes the part you look at.

Deference, not chrome

Help, presets, set type, special sets and Discard fold into system menus. Six permanent objects become one glass capsule and a long-press. The rest timer keeps its own tap, because you arm it mid-workout — see the capsule below.

Marks obey their own grammar

Ringed glyph leaves — Add exercise opens the picker, so it is a door row with a ring. Bare plus grows — Add set appends a row, so it is a bare plus with no box at all.

4 – What should be native SwiftUI, and why

The kit already renders real SwiftUI on iOS through @expo/ui, and it already has a doctrine: nativize controls, never the brand. The gap is that this screen hand-rolls seven things the system does better — and the line between the two moves the moment a control stops wearing brand paint.

Make these native

The toolbar capsule

Destructive rows get the system's red and its semantics for free, and the radio-with-checkmark is the pattern every iPhone owner already reads. The toolbar capsule — and where the rest timer lives

The ⋯ in Apple Music is not a glyph with a circle drawn round it. It is a native SwiftUI button inside a GlassEffectContainer, sharing one lozenge with the button beside it — two leaves, one piece of glass, and when either is pressed the material itself answers: the specular rim travels, the capsule bounces, the menu zoom-morphs out of the anchor. That is the thing we want, and the kit can already build it. GlassPillRow does the fusing today for the nav dock; it just draws glass and lets React Native handle the taps. A toolbar group is the same construction with real Button and Menu leaves inside, so the touch lands on SwiftUI.

Which answers the second question too. A capsule wants two related actions, and this screen has exactly two: the rest timer and everything else. So the timer is not buried in the menu — it is the left half of the capsule, one tap to arm or disarm, mid-set, with the duration reading out beside the symbol when it is on. The durations live one level in, as an inline picker in the menu next to it, which is where a value you change once a month belongs.

The capsulethree states
⏱⋯ OFF – tap to arm
⏱ 1:30⋯ ARMED – tap to disarm
⏱ 0:47⋯ RESTING – counts down in place
  • ✓Armed, the symbol fills and takes the blue it already uses in the rest banner. Off, it is ash. State is in the mark, not in a word.
  • ✓While a rest is running the same slot counts down, so the capsule is a clock when there is a clock to show and a switch the rest of the time.
  • ✓Long-press it, or open the ⋯ beside it, for the durations — the existing GlassSelectMenu, unchanged.
How it's builtswiftui.tsx
// One Host, one container, two native leaves — the composition rule
// holds better than today, where the timer chip and the menu are two
// separate Hosts sitting next to each other pretending to be a group.
<Host matchContents>
  <Namespace id={ns}>
    <GlassEffectContainer spacing={2}>
      <HStack spacing={2}>

        {/* LEFT — the rest timer, one tap */}
        <Button onPress={toggleRest}
          modifiers={[buttonStyle("glass"), accessibilityLabel(restA11y)]}>
          <HStack spacing={5}>
            <Image systemName={armed ? "timer" : "timer.slash"}
              color={armed ? blue : ash} />
            {armed && <Text>{mmss(remaining ?? restSeconds)}</Text>}
          </HStack>
        </Button>

        {/* RIGHT — the menu, exactly the Apple Music slot */}
        <Menu label={<Image systemName="ellipsis" />}>
          <Picker selection={restValue} onSelectionChange={pickRest}>
            …Off / 60 s / 90 s / 2 min / 3 min
          </Picker>
          <Divider />
          <Button label={whatsRpe} onPress={openRpeHelp} />
          <Button label={saveRoutine} onPress={openRoutine} />
          <Button label={discard} role="destructive" onPress={discard} />
        </Menu>

      </HStack>
    </GlassEffectContainer>
  </Namespace>
</Host>

Every import is already in swiftui.tsx. Gate it on LIQUID_GLASS_RENDERED like the other leaves, and keep the RN pair — a bordered ⏱ chip and a ⋯ — as the floor for Android and pre-26 iOS. Web draws the same two-slot lozenge in .liquid-glass with a hairline between the halves; it is one capsule there too, so the two clients read as one product.

One piece of state, three places it shows, no contradiction between them: the capsule (armed or not, and counting when it counts), the dock hint under the set you are about to bank (REST 1:30 AFTER / NO REST TIMER), and the Dynamic Island once ActivityKit lands. Today it shows in one place, as a chip in the row you read least.

The dock cluster — one filled pill, two glass satellites

This is a shape the product has already chosen once. The finish summary ships a lime Share pill flanked by two glass satellite orbs, with the app's one exit as a third — finish-liquid-field, and it works. The live screen should end the same way, because it is the same sentence: one thing you do, two things you can do to the session itself. Pause and Finish are not peers of Log set and should never be drawn as peers; they are satellites, and satellites are glass.

The clusterrecommended

Pause is a circle, because pause.fill is a glyph nobody has to read. Finish is a labelled capsule, because ending a session is the one thing on this screen that should never be guessed at. The asymmetry is the point: they are not equals. Pause is reversible and frequent; Finish happens once.

The symmetric variantnot recommended
❚❚ ✓ Log set ⚑

Prettier, and it matches the finish screen's two-orb balance exactly. But a bare chequered flag is a guess, and the thing it does cannot be undone by tapping it again. If we take this one, it needs a confirm — at which point the label was cheaper.

How it's builtswiftui.tsx
// GlassSatellite — the same construction as GlassNavButton, with the
// shape and an optional label opened up. Two callers today; the finish
// screen's orbs are the third once they come off their RN drawing.
<Host style={{ width: hit, height: hit }}>
  <Button onPress={onPress}
    modifiers={[buttonStyle("plain"), accessibilityLabel(label)]}>
    <HStack spacing={6}>
      <Image systemName={glyph} size={glyphSize} color={fg} />
      {word && <Text modifiers={[font({ family: F.bold, size: 15 })]}>
        {word}
      </Text>}
    </HStack>
    // chain order IS the construction: size the content, glass THAT
    // shape, then pad the frame out to the 44pt target and make the
    // whole frame tappable — circle for the orb, capsule for the pill.
    </>.modifiers([
      padding({ horizontal: word ? 16 : 0 }),
      frame(word ? { height: 44 } : { width: 44, height: 44 }),
      glassEffect({
        glass: { variant: "regular", interactive: true },
        shape: word ? "capsule" : "circle",
      }),
      contentShape(word ? shapes.capsule() : shapes.circle()),
    ])
  </Button>
</Host>

// pause.fill / play.fill for the orb — it swaps in place, amber when
// held, and the elapsed clock in the header goes amber with it.
// flag.checkered for Finish. NOT xmark: an X reads as discard, and
// discard is a different, destructive row inside the menu.

glassEffect already takes shape: "capsule" in the installed @expo/ui, so the labelled pill is one modifier away from the circle we ship today. Gate on LIQUID_GLASS_RENDERED, keep the RN pair below it, and web draws both in .liquid-glass — the rim grammar it already uses on the logger's chevron.

One risk, stated: this parks a terminal action permanently beside the button pressed thirty times a session. It is survivable — Finish saves and lands on the summary, where the session can be renamed, edited or deleted, so a mis-tap costs a broken set, not data. Still: give Finish a confirm when queued sets remain unbanked, and let the two satellites sit on the outer edges with the pill centred, so the thumb's resting arc falls on chartreuse.

The first five are bugs and cost almost nothing. Everything below the line is the redesign, and every step of it has to land on web in the same change.
