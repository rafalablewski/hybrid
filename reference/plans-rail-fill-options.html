HYBRID · PLAN ROW — FILLING THE EMPTY RAIL

5 ways to fix the lonely single chip

The rail only looks good with multiple blocks. Most hypertrophy plans have one prescription per exercise, so the rail sits empty. Each option below is shown on both a single-prescription PPL exercise and a multi-block OWL lift — the layout has to look intentional on each.

Adaptive Leader

The row changes layout by chip count. One block → a clean list line: name left, a dotted leader fills the gap, prescription right (no empty rail). Many blocks → the chips group on the right. Nothing ever floats alone.

+ minimal, elegant, zero wasted space– two code paths per row

Stat Chips

Stop treating the prescription as one blob — break it into labelled stat chips: SETS · REPS · RPE · (LOAD). A single PPL exercise now fills the rail with 3–4 meaningful chips; OWL keeps its per-load chips. Every lift looks populated.

+ always full, scannable, consistent– more chips = busier

Per-Set

Render one chip per actual working set. PPL "4×6" → four "×6" chips; OWL stays per-load. The space fills proportionally to volume, and it doubles later as a tap-to-log checklist (tick each set as you go).

+ fills naturally, great for logging– 5×10 = 5 identical chips (repetitive)

Name-Top Stack

Drop the pinned column. Name owns the top line (with a set×rep summary on the right); the prescription sits below as a chip, flanked by muted context chips — rest, tempo, target load, "main lift". A single exercise still fills the row because the secondary data balances it.

+ no empty space ever, richest context– taller rows (less fit on screen)

Metric Grid

Each exercise carries a small always-filled grid — SETS / REPS / RPE cells for hypertrophy, a tiny load-ramp mini-bar for OWL. It's a fixed block, so it's never empty and every row aligns. The most "dashboard", most uniform option.

+ uniform, dense, perfectly aligned– most rigid / least playful
