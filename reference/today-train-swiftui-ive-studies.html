Today → Train,
rebuilt in SwiftUI.

Seven proposals for the logbook card — the block that carries Your training, the week strip and the day's receipt. Each one trades a hand-drawn React Native imitation for the control iOS already ships, and each is measured against the same brief: less drawing, more material; fewer edges, more air; one hierarchy instead of two.

The card is honest and it works. What it isn't, is native. Every element in it is drawn: the border, the shadow, the three full-bleed hairlines, the seven flex chips, the dashed square, the two competing pills. None of it is a control the system owns, so none of it inherits the system's material, motion, or accessibility for free.

Count what the eye has to get past before it reaches a fact: Today → Train → Your training → Last 7 days → Nothing logged yet. Five headings, and the first four are all names for the same thing.

The specific charges
  • 01A drawn box and a shadow and a border and three hairlines — four separation devices where the system uses one.
  • 02The week is a fixed Wed→Tue window that can't be scrolled, so the label has to say LAST 7 DAYS because the control can't show it.
  • 03Two actions drawn at the same weight in two different vocabularies — a glowing full-bleed pill, and a dashed ＋ tile forty pixels below it. Both belong here; only one can be first.
  • 04🎾 as content. Emoji don't tint, don't take weight, don't respond to Dynamic Type, and redraw themselves on every OS update.
  • 05The tab bar smears "Train your way" into an unreadable ghost — a hand-rolled blur doing a job scrollEdgeEffectStyle does properly.
  • 06Changing day remounts on key={sel.dateKey}. Values hard-cut. Nothing in the card is animated at all.

The border, the drop shadow and the solid ink2 fill are three ways of saying "this is a surface". Say it once, with the material the OS already renders: GlassSurface is in the kit and this card doesn't use it.

Then fix the corners. iOS 26 made concentricity a rule rather than a taste: a nested radius equals its parent's radius minus the padding between them, so every corner in the stack shares one centre. Today the card is 28, the session tile inside it is 12, and they are drawn on unrelated arcs — which is why the tile reads as pasted on rather than set in.

One seam survives: the line between the week and the day, because that is a genuine change of subject. The other two hairlines separate things that were never confusable, and they go.

The delta
  • −logbook-rail.tsx:91-102 — drop borderWidth, borderColor, shadowOpacity, elevation.
  • +Mount <GlassSurface radius={RADIUS.card} /> behind the content (already exported from aurora/swiftui.tsx:88).
  • +Add RADIUS.concentric(parent, pad) to kit.tsx:36 and derive every nested radius from it.
  • −Two of three hairlines: logbook-rail.tsx:120 stays, done-floor.tsx:86 becomes whitespace.
House rule kept "Stacked rows separate by whitespace, not a rule" is already in CLAUDE.md — this applies the rule the card was written before.

Seven flexed chips can only ever show seven days, which is why the header has to carry a LAST 7 DAYS caption explaining the control's own limits. Replace it with a horizontal ScrollView under scrollTargetBehavior(.viewAligned) and the caption evaporates — history is simply there, to the left, as far back as the account goes. That frees the header's right slot for the exit into History.

The selection becomes the same Liquid Glass lens the app already ships in liquid-seg.tsx: inside a GlassEffectContainer, tagged with glassEffectId, so moving between days flows the lens rather than repainting a chip. One selection material app-wide is the point — the segmented switcher at the top of Today and the day picker below it should not be two different ideas of "chosen".

And the ✓ becomes a load bar. A tick says something happened; a bar the width of the day's relative load says how much, in exactly the same pixels. Seven days of bars is a training week at a glance — which is the whole reason the strip exists.

The delta
  • −logbook-rail.tsx:113-117 — the fixed flexDirection:"row" chip row and DayChip's three-slot layout.
  • +GlassDayRail in aurora/swiftui.tsx: GlassEffectContainer + glassEffectId, driven by the same springs token liquid-seg uses.
  • +logbookWeek() in core widens to logbookDays(range) and returns a per-day load (0–1, from the same figures the receipt uses — through deviceTrueSession).
  • −The w.home.logbook.window string. The control no longer needs a caption to describe itself.
House rule kept Screen-level rails run full-bleed: negative margins the width of AuroraScreen's 12dp gutter, matching internal padding, so a resting day still lands on the content column.

Log a sport stays. It isn't an overflow item — it is a genuinely different job from the structured logger: a session you start (live, now, sets and reps), a sport you log (it already happened, and you're telling the app about it). Bury it in a menu and a hybrid athlete's most common Sunday-evening action costs two taps and a guess.

So the fault isn't that both exist — it's that they're drawn at the same weight in two different vocabularies. A glowing full-bleed chartreuse pill. Then a hairline. Then a whispered caption. Then a dashed square with a lime word beside it. That's four devices spent on saying "and also this", and a dashed border is a web affordance that appears nowhere in iOS.

iOS says it in one move: a filled primary with a neutral capsule beside it. The kit already has that component and its argument written down — GlassSatellite (swiftui.tsx:259), "a neutral glass button that orbits a filled primary", explicitly sanctioned as the case that doesn't touch brand paint. It was built for the logger's Pause and Finish. This is the same shape: one lime pill, one glass capsule, one baseline.

And the state change becomes a fill change rather than a layout change. Nothing logged: Start a session wears the chartreuse. Once the day holds training, the accent retires and the two settle into equal glass capsules that fuse into a single lozenge — the GlassEffectContainer behaviour the app already ships in GlassToolbarGroup. The card stops asking without anything moving.

The delta
  • −done-floor.tsx:145-152 — the dashed ＋ tile. The action survives; its box doesn't.
  • +GlassSatellite (swiftui.tsx:259) with word="Log a sport" and glyph="figure.mixed.cardio", keeping the RN capsule fallback it already ships off-iOS.
  • +AActionPair in kit.tsx — primary + satellite, wrapped in a GlassEffectContainer so the logged state can fuse them.
  • +AEmptyState — symbol / title / one line / the pair — so History, Nutrition and Messages stop inventing their own.
  • −w.home.today.alsoTodaySubEmpty ("a match, a run, a swim"). The capsule is now labelled, so the invitation is said once, in the description line.
House rules kept The no-bordered-box rule governs exits — an end-of-thing affordance that carries no content. This is an action, and a capsule is its native form. The rule that binds here is the other one: chartreuse stays reserved for the single primary, which is exactly what the satellite protects.
One copy call to veto Start a session against Log a sport: the verbs differ on purpose, because the tense does — one is about to happen, one already did. If you'd rather keep "Log a session", the pair still works; it just leans on the noun alone to carry the difference.
04

SF Symbols instead of emoji. Tint instead of tiles.

A glyph that inherits weight, colour, and the OS
The done row

Proposed figure.tennis · tinted circle
1 done — Mon 10 Aug
Tennis 4.11 km – 81 min – 19:49 /km
Lower — Strength 6 lifts – 14 sets – 4 820 kg Plan

sessionIcon(s) returns an emoji, and the row sets it at 18 pt inside a 12 pt-radius tinted square. Three problems, all structural: an emoji can't take the row's colour (so the tile has to be tinted around it to carry meaning), it can't take a weight or an optical size, and Apple redraws the whole set every couple of releases — the app's icon language silently changes under it.

The kit already exports the SFSymbol type (swiftui.tsx:69) and uses symbols for chrome — arrow.left, ellipsis, timer — but never for content. Extend it: figure.tennis, figure.run, figure.pool.swim, dumbbell.fill. Hierarchical rendering, one tint, a circle instead of a squircle so the glyph reads as a mark, not a tile.

The payoff is off-screen as much as on: a symbol is the only glyph that survives into a widget, a Live Activity, a Watch complication and a Spotlight result at the right weight — see 07.

The delta
  • +sessionSymbol(s): SFSymbol beside sessionIcon in core, so one map drives both and the emoji stays as the off-iOS fallback.
  • +GlassSymbolMark in swiftui.tsx — symbol, tint, circle, optional symbolEffect(.bounce) when a session lands.
  • −done-floor.tsx:116-118 — the 40×40 RADIUS.inner emoji tile.
  • +The row's meta line moves to the spaced en dash, per the no-middot rule.

Look at the second screenshot's lower third: "Train your way" and the plan cards are smeared — two layers of text ghosting through a hand-rolled blur while the tab bar floats over them. That is a hard problem solved badly, and iOS 26 solves it in one modifier: scrollEdgeEffectStyle(.soft) gives the system's progressive fade at the scroll edge, computed against whatever is actually passing under the bar.

At the top, the same trade. Today and the date sit as static text that simply scrolls out of view, so the header keeps its full height forever. A real large title collapses into the glass bar on scroll — the wordmark, the streak and the day condense into one 44 pt lockup, and the section gets back roughly 120 pt of first-screen space. On a 6.1 inch phone that is the difference between the day's receipt being visible on load and needing a scroll.

The Train/Analyse/Social switcher stays exactly where it is — it is already the right control (liquid-seg.tsx), and it is the one piece of chrome that earns its place above the fold.

The delta
  • +AuroraScreen (kit.tsx:230) grows a largeTitle slot that hands the title to the native header instead of rendering it in flow.
  • +scrollEdgeEffectStyle on the Today scroller, gated behind LIQUID_GLASS_RENDERED.
  • −The manual auroraScrollClearance() bottom padding, once the system owns the edge.
  • +Fold "Train your way" into the same rail idiom as 02 so both sliders under the fold behave identically.
06

The day is a value you scrub — and the numbers roll to meet you.

Mid-scrub — the hero figure counting between days

Haptic detent per day · numbers use contentTransition(.numericText())

Right now the day changes by tapping a chip, and the detail block remounts under a key={sel.dateKey}. Every figure hard-cuts. Nothing tells you whether you moved forward or back, and nothing connects the number that left with the number that arrived.

Make the day a value. Swipe anywhere on the card and the rail and the detail move as one gesture, with a haptic detent per day — the same directness the app already commits to in GlassWheel, where selection applies as the wheel settles rather than on a confirm. Then let the figures do what SwiftUI figures do: contentTransition(.numericText()) rolls 4.11 → 12.40 digit by digit, in the direction of travel.

This is the one place to spend motion. Everything else in these seven proposals gets quieter; the number earns the exception because the number is what the card is for. The backlog already asks for it — mobile-stat-tile, "so its figures can roll too".

The delta
  • −logbook-rail.tsx:123 — the key={sel.dateKey} remount, which is what makes the change a cut.
  • +ARollingFigure in the kit: native contentTransition on iOS, a Reanimated digit column elsewhere, one API.
  • +A pan gesture on the card mapped to the rail's index, with haptic("selection") per detent (lib/haptics exists).
  • +Honour useReducedMotion() — the rolls collapse to instant, exactly as liquid-seg already does.
Watch out Figures must keep coming through deviceTrueSession(). A rolling number computed from display-rounded values would animate to a figure the device panel beside it contradicts.
07

The card's best form may not be inside the app at all.

One data shape, four surfaces
The same receipt, rendered by the system
Home screen — small 4.11 km
Live Activity Set 3 of 5rest 0:42
Control Center ＋ Log a set

@bacons/apple-targets is already a dependency and nothing uses it. The logbook card is the single best candidate in the app for extension, because it is already the right shape: a week of load, one hero figure, one action. That is a small widget, an accessory complication, a Live Activity and a Control Center control without inventing any new data.

This is the strongest argument for 04. A widget can't render an emoji at the right weight against a tinted Lock Screen, and it certainly can't render a React Native view — but logbookWeek() is already pure core TypeScript, and an SF Symbol is the only glyph that draws identically in SwiftUI, WidgetKit and the Watch.

It also fixes the app's weakest moment. Logging a set today means unlock → app → Today → card → session. From the Lock Screen it is one press.

The delta
  • +An apple-targets widget extension reading a shared App Group snapshot written after every save.
  • +logbookSnapshot(sessions) in core — the one serialisable shape the widget, the Live Activity and the card all read.
  • +Four capabilities.ts entries, opening as planned; the widget goes blocked until the App Group is provisioned on the Apple account.
Sequencing Native targets change the prebuild, so this must not ride in the same TestFlight build as the card work — one variable per build, per the Expo-module rule that already governs this repo.

Nine deletions against five new shared components — and the section keeps every capability it has today, Log a sport included. Every row above removes a drawing, never an action. That ratio is the point of the exercise: an iOS redesign that adds surfaces isn't one.

Build order

three TestFlight builds
Build 1

01 + 03 + 04 — the still frame

Pure JS, no native change, shippable over EAS Update. The card loses its box, the two actions resolve into a primary and its satellite, the rows lose their emoji. Nothing animates yet and the section already reads native — this is the build that proves the direction on a device before any gesture work is paid for. It is also the one that puts Log a sport on the same baseline as the logger, which is worth watching in the numbers on its own.

Build 2

02 + 06 — the rail and the roll

The week becomes a scrollable rail with the glass lens; the day becomes a scrub; the figures roll. This build needs a device round for the GlassEffectContainer geometry — the same verification loop swiftui-kit already documents — and it must land logbookDays(range) in core with tests before any UI touches it.

Build 3

05 + 07 — the screen and the surfaces beyond it

The large title, the scroll edge effect, then the widget target. Both change native config, so they ride their own prebuild. 07 opens blocked in the capabilities registry until the App Group exists on the Apple Developer account.

Two constraints that outrank all seven Every figure on this card must keep reading through deviceTrueSession() — a redesign is exactly when a surface quietly starts drawing typed values again. And each proposal ships with its capabilities.ts entry in the same change; the mobile card is now the golden standard on its own, since the user-facing web client was retired in August.
